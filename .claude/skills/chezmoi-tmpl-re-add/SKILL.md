# chezmoi-tmpl-re-add

`chezmoi re-add`는 템플릿 소스를 수정하지 않는다. 이 스킬은 로컬 파일의 변경을 `.tmpl` 소스에 직접 옮긴다. 방향은 항상 로컬 → 템플릿이다.

## 절차

1. 대상 파일을 찾는다.
   - `chezmoi status`를 실행한다. 두 번째 열이 `M`인 항목이 로컬과 소스가 다른 파일이다.
   - 각 항목에 `chezmoi source-path ~/<경로>`를 실행하고, 결과가 `.tmpl`로 끝나는 파일만 대상으로 삼는다.
   - 대상이 없으면 그 사실을 보고하고 끝낸다.

2. 파일마다 `chezmoi diff ~/<경로>`로 차이를 확인한다.
   - `-` 줄이 로컬의 현재 내용이고, `+` 줄이 템플릿 렌더 결과다. 템플릿에는 `-` 쪽 내용을 넣는다.

3. 차이를 hunk 단위로 분류한다. 템플릿 소스에서 같은 위치를 읽고 판단한다.
   - **반영**: 해당 줄과 주변에 템플릿 표현식이 없는 일반 텍스트.
   - **보고만**: 해당 줄에 `{{ ... }}` 표현식이 있는 경우. 로컬 값으로 덮어쓰지 않는다.
   - **보고만**: `{{ if }}`, `{{ range }}`, `{{ with }}` 블록 안에서 차이가 나는 경우.

4. 반영으로 분류한 hunk를 Edit로 템플릿에 옮긴다. 사전 확인은 받지 않는다.
   - 같은 내용이 여러 번 나오면 `chezmoi diff`의 hunk 개수와 템플릿의 등장 횟수가 일치하는지 확인한 뒤에만 `replace_all`을 쓴다.

5. `chezmoi diff ~/<경로>`를 다시 실행해 검증한다.
   - 보고만 하기로 한 hunk 외에 차이가 남아 있으면 템플릿을 다시 읽고 고친다.

6. 결과를 보고한다.
   - 수정한 템플릿과 반영한 항목
   - 반영하지 않은 항목: 파일, 줄, 로컬 값과 렌더 값, 반영하지 않은 이유
   - 검증 결과 (`chezmoi diff` 출력이 비었는지)
   - 제안 커밋 메시지 한 줄

## 하지 않는 것

- `chezmoi apply`를 실행하지 않는다. 로컬 변경이 템플릿 값으로 되돌아간다.
- `git commit`, `git push`를 실행하지 않는다.
- `.chezmoidata.*`, `chezmoi.toml` 등 템플릿 변수 값을 수정하지 않는다.
- 템플릿이 아닌 파일은 수정하지 않는다. `chezmoi status`에 남아 있으면 `chezmoi re-add` 대상이라고 보고만 한다.
- 로컬에 파일이 없는 항목(`chezmoi status` 두 번째 열 `A`)과 암호화된 소스(`encrypted_`)는 건너뛰고 보고한다.
